**Scene 2: Learn to direct AI, not just use it**  
**Narration:**  
GitHub advises learners to focus on directing AI agents effectively. That means giving clear context and critically evaluating multiple AI outputs before accepting code. AI can generate impressive solutions quickly, but the first answer isn’t always the best. For example, GitHub suggests asking a second AI model to critique the first model’s work, then using your own judgment to decide which code to trust. This approach helps catch errors and improves code quality.

**Scene 3: Customize AI behavior with instructions and canvases**  
**Narration:**  
You can tailor AI agents to your project using custom instructions and canvases. GitHub Copilot lets you add a `.github/copilot-instructions.md` file to your repo to define your project’s architecture, naming conventions, or testing expectations. This means you don’t have to explain the same rules repeatedly.  
Canvases are customizable interfaces you create by describing your workflow in plain English. For example, you can build a kanban board or release checklist that the AI and you update together in real time. This shared workspace helps you steer the AI’s work interactively and reduces repetitive explanations.  
Start small by adding one project convention as a custom instruction and see how Copilot applies it next time.

**Scene 4: Voice-driven coding can speed up simple features**  
**Narration:**  
Simon Willison demonstrated building a new blog feature almost entirely by voice, chatting to his laptop while cooking dinner. Using Codex’s voice mode, he described the feature, gave clarifications, and let the AI write and test code. This workflow enabled multitasking and accelerated development of straightforward features.  
However, he still reviewed and tweaked the AI’s output before deploying. Voice-driven coding is promising for simple tasks but may not replace traditional typing workflows yet.

**Scene 5: Delegating implementation frees you to focus on higher-level skills**  
**Narration:**  
When AI saves you time on implementation, you can focus on bigger problems: defining the problem clearly, evaluating tradeoffs, designing better systems, and making technical decisions AI can’t make. GitHub emphasizes that as AI takes on more coding, your judgment and decision-making skills become even more important.

**Scene 6: OpenAI’s Computer Use agents can run complex tasks autonomously**  
**Narration:**  
OpenAI’s Computer Use agents run on Linux virtual machines in the cloud. They can perform complex, multi-step tasks autonomously, like booking meals or managing apps. For example, one user saved two hours by delegating a complicated meal order to a Computer Use agent, which completed it eight times faster than manual effort.  
This shows learners can delegate more complex tasks but must still review outcomes carefully.

**Scene 7: Watch for tools that improve AI reliability and intervention**  
**Narration:**  
New research and tools are emerging to help you know when to trust AI and when to intervene. For example, HiSentinel is a lightweight system that predicts when AI actions need human review before execution, preventing error propagation and improving reliability.  
GitHub’s ReviewBench is an open benchmark that measures AI code reviewers’ strengths and weaknesses, helping you understand which AI tools catch critical issues and which produce noise.  
Keeping an eye on these tools can help you safely delegate more programming tasks over time.

**Scene 8: AI can handle complex software rewrites, but with effort**  
**Narration:**  
A recent project rewrote the entire TypeScript compiler in Rust using AI agents. This complex task took months and cost hundreds of thousands of dollars in compute tokens. The result is a faster compiler, but it required significant resources and careful verification.  
This shows AI can handle ambitious projects, but learners should understand the scale and effort involved before delegating such tasks.

**Narration:**
